# 出力名の大小文字・Unicode・別名の競合を修正

2026-10-12。追加点検で、このMacのファイルシステムでは`Design.ai`と`design.ai`が同じファイルになるのに、CLIが別々の出力先と判断する問題を再現した。異なるフォルダーの`Design.pdf`と`design.pdf`を同じ出力フォルダーへ`--overwrite`付きで変換すると、成功を返しながら出力が1ファイルだけになり、先の結果が後の結果で置き換わった。

出力先の重複検査を`src/pdf2ai/path_conflicts.py`へまとめ、実際の保存先ファイルシステムの名前比較で競合を確認するよう変更した。保存先の隔離した一時フォルダー内で候補のファイル名を排他的に作成し、大小文字やUnicode正規化の違いが同名になる場合は変換・公開前に拒否する。一時フォルダーは検査後に削除する。大小文字を区別するボリュームでは、区別できる名前を一律に小文字化して拒否しない。

CLIの複数入力・ページ出力・レポート、Scribusの一括公開に適用した。入力と出力・レポートの競合は、パス表記だけでなく実際の同一ファイル判定も使い、ハードリンク等の別名も拒否する。通常のAI保存と上書き方式は維持する。

この環境で全386テスト成功。追加16件では、大文字小文字・Unicodeの別表記、単ページ・結合、上書き有無、公開前の競合拒否、入力・ステージングファイルの保持、検査用ファイルの削除、レポート競合、入力へのハードリンクを確認した。実際の名前比較が異なる環境では、該当する競合の実機テストをスキップし、保存先の比較規則に従うことを別途検査する。

別の一時ファイルによる確認では、回転4種×UserUnit2種×CropBox有無×ベクター／画像化の32通りについて、単ページ出力と順序を入れ替えた結合出力のPDF表示が元と一致した。今回、参考用のAIは変更していない。

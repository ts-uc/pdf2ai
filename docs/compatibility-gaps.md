# 残る互換性の課題

2026-10-11。vector.py、fonts.py、layers.pyの拒否条件と実機検証結果を照合した一覧。テスト件数や保存成功だけで、全機能対応・全ファイルの見た目の一致を保証するものではない。

| 分野 | 未対応・制限 | 変換時の影響 |
| --- | --- | --- |
| 色管理 | 一般のLab、DeviceN、複数インク、非線形の特色濃度関数、ICCの非標準Range／対応外のチャンネルモデル、ICC付きグラデーション、元プロファイル・インク成分の編集保持 | ICCのRGB/CMYK/グレーの画像・塗り・線はsRGBへ変換してベクター保持。8ビット量子化あり。RGB文書のDeviceCMYK画像はPDF描画器のRGBへ明示変換する。全カラー設定・OutputIntentでの一致は未保証 |
| 透明処理 | 図形のソフトマスク、ページ全体の分離・ノックアウト、文書と異なるグループ色空間、グループ内のレイヤー切替 | Formの分離・ノックアウト・不透明度・描画モード・入れ子と、塗り＋線の分割に必要なノックアウトは対応。残る条件はページ全体の画像化 |
| テキスト | 文字としての編集、縦書き、Type3、Identity-H以外のCIDエンコーディング、一部のCMap・未埋め込みフォント | 対応フォントも輪郭として編集。未対応は画像化。フォントによっては前処理の利用で結果が異なる |

## 実機検証がまだ不足している点

- ユーザーのDIC 448の文字が太く見える実例は未確認。合成例で文字の太りがなかったことだけでは原因を確定できない。
- 現在の実機確認はIllustrator 30.8.2、Scribus 1.6.6が中心。他のバージョンやカラー設定での同一結果は未保証。
- 元PDFの表示を保持する確認と、Illustratorが編集データから再保存したPDFの比較は別の検証。画像化したページでは文字・特色分版・レイヤーが失われる。
- 実際の入稿データで、特色分版・オーバープリント・OutputIntentを含めて検証する余地がある。

## 次に優先して改善する対象

図形のソフトマスク、ページ透明グループ、OutputIntentを含む色管理、曲線近似の精度・処理量、実制作データの検証。文字の編集可能性、ICCグラデーション、特殊なフォントや条件付きレイヤーは、データ構造や描画の検証を伴う課題。

# 残る互換性の課題

2026-10-11。vector.py、fonts.py、layers.pyの拒否条件と実機検証結果を照合した一覧。テスト件数や保存成功だけで、全機能対応・全ファイルの見た目の一致を保証するものではない。

| 分野 | 未対応・制限 | 変換時の影響 |
| --- | --- | --- |
| 色管理 | 一般のICC/Lab、DeviceN、複数インク、非線形の特色濃度関数 | 原則ページ全体の画像化。RGB文書のCMYK画像は変換可能でもIllustrator再保存後に表示差が残る |
| 透明処理 | 図形のソフトマスク、分離・ノックアウトの透明グループ、Form全体の透明度、半透明の塗りと線の同時描画を別操作に分割するケース | ページ全体の画像化。画像のソフトマスクへの対応とは別 |
| テキスト | 文字としての編集、縦書き、Type3、Identity-H以外のCIDエンコーディング、一部のCMap・未埋め込みフォント | 対応フォントも輪郭として編集。未対応は画像化。フォントによっては前処理の利用で結果が異なる |
| 線 | 適応分割の上限を超える曲線・尖点・特異な曲線、丸以外の線端で長さ0を含む破線、180度折り返す結合、ヘアライン、グラデーションの線 | 対応範囲外は画像化。曲線は近似で輪郭化する。輪郭化した線は線幅として編集できない |
| グラデーション | メッシュ、開始半径が0でない円形、焦点が終端円の外／境界にある円形、円形の非等方拡縮・せん断、Extendなし、特殊な関数・不連続な色変化 | ページ全体の画像化。対応した非線形関数も有限個の停止色で近似 |
| パターン | タイルパターン、追加の描画状態を持つシェーディングパターン | ページ全体の画像化 |
| 画像 | インライン画像、IndexedのDecode／Matte、寸法が異なる透過マスク、入れ子のマスク、一部の特殊なDecodeやフィルター | ページ全体の画像化。16ビット対応画像・マスクは8ビットに丸める。JPEGやMatte復元には丸め誤差がある |
| レイヤー | OCMDの条件式、別レイヤー条件の入れ子、排他表示、ズーム・言語等による自動表示 | ページ全体の画像化。単純なレイヤーの表示・ロック・印刷属性とは別 |
| PDF固有の情報 | 注釈、フォーム入力、リンク等の対話機能、PDF/Xの再認証 | 注釈を含むページは画像化。AIの編集データにPDFの対話機能を再構築しない |
| 容量・座標 | 標準キャンバス、アートボード数、パス／画像サイズ、破線の展開量 | 上限超過は拒否または画像化。全ファイルへの無制限対応ではない |

## 実機検証がまだ不足している点

- ユーザーのDIC 448の文字が太く見える実例は未確認。合成例で文字の太りがなかったことだけでは原因を確定できない。
- 現在の実機確認はIllustrator 30.8.2、Scribus 1.6.6が中心。他のバージョンやカラー設定での同一結果は未保証。
- 元PDFの表示を保持する確認と、Illustratorが編集データから再保存したPDFの比較は別の検証。画像化したページでは文字・特色分版・レイヤーが失われる。
- 実際の入稿データで、特色分版・オーバープリント・OutputIntentを含めて検証する余地がある。

## 次に優先して改善する対象

RGB文書内のCMYK画像の再保存時の色処理、曲線近似の精度・処理量の改善、図形のソフトマスクと透明グループ。文字の編集可能性と汎用ICC対応は、データ構造や色管理の設計を伴う大きな課題。

最新の実機比較・対応範囲の拡張は ../output/fidelity-check/README.md と technical.md に記録する。

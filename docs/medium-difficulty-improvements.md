# 「中」「中〜高」の課題への対応

2026-10-12。[実装前の棚卸し](remaining-issues-and-difficulty.md)のうち、保存・結合検査・画像・線・PDF入力・運用・検証を対象に対応した。以下の対応範囲を超える条件まで、すべて対応したという意味ではない。

## 実装した内容

| 対象 | 対応 | 残る範囲 |
| --- | --- | --- |
| CLIの複数出力 | 全件を保存先と同じファイルシステムへ仮保存し、全件成功後に一括公開。別ファイルシステムのバックアップは保存先の一時ファイルを経由して復元。後の変換失敗では先のAIも公開しない | 強制終了・停電・並行上書きの完全な一式保証は別の高難度課題 |
| CLIのAIとJSON | 同じ公開・復元処理へ統合。レポート書込み・公開の失敗でも既存のAIとJSONを保持 | 変換失敗時のJSONは新規保存せず、失敗理由を標準エラーへ表示 |
| 結合前検査 | 配置・最終文書色空間・透明グループ・同名特色の定義・最終編集データ生成まで変換と共通の処理で検査。CLIの`--check --combine`とScribusに適用 | 各ページの未対応理由は依然として最初の1件。検査後のファイル変更や保存障害は別 |
| インライン画像 | 実際に呼び出すページ・Formのストリームだけを外部画像へ展開して読み込む。不要な深いFormや循環定義は再帰走査しない | 展開後の画像自体が対応外なら従来どおり画像化 |
| 画像ColorSpace別名 | リソースの参照範囲を使って解決。PDF表示側も画像を参照範囲ごとに複製して別名を展開。共有画像・共有XObject辞書を異なる色空間で参照する場合も保持 | 循環・欠落・対応外の色空間は拒否。一般のDeviceN等は今回の範囲外 |
| 異なる寸法の透過マスク | 非補間の色画像とマスクを最小公倍数の共通画素格子へ展開。小さい・大きい・整数倍でないマスクも、元の画素境界を保持。展開後4,000万画素を上限とする | 補間・入れ子等は画像化。Matteのあるマスクは同寸法が必要。描画器の境界処理・量子化による比較差は残る |
| Indexed画像のMatte | 親のIndexed色空間における1つのパレット番号から背景色を求め、混合を解除 | 不正な成分数・パレット番号・寸法は拒否。低い透過率による量子化差は残る |
| Adobeの線補正指定 | `/SA`が有効でも塗りだけの図形を画像化しない。再生成で見つかった過去のDIC2例をベクター保持できるよう修正 | 実際に線を描く場合の装置依存の補正は引き続き拒否 |
| 特殊な非等方の線 | 通常・丸・突出の線端の長さ0を含む破線、180度折返し、丸い線端の長さ0の直線・曲線を輪郭化。移動命令だけのサブパスは描かない | ヘアライン、特異変換、グラデーションの線、近似・展開上限は残る |
| 同色空間のページ透明グループ | RGB/CMYKの分離・ノックアウトを編集データに保持。PDF表示側はノックアウトを明示的なFormグループへ移し、入力の構造を読み違える描画器でも一致させる | レイヤーを含む場合、異なるグループ色空間、図形のソフトマスクは今回の範囲外 |
| パスワード付きPDF | CLIで非表示入力またはUTF-8ファイルの先頭行から取得。APIの`password=`でも指定可能。作業用コピーだけを復号し、元PDFを変更しない | Scribusは自身の非暗号化PDFを書き出すためパスワード画面を追加しない。不正なパスワードでは保存しない |
| 注釈・フォームの外観 | `--flatten-annotations`で通常のページ内容に取り込み、対応する図形をベクター保持 | コメント・添付・フォーム操作等の対話機能はAIへ復元しない。取り込んだ図形自体の対応範囲は通常変換と同じ |
| 結合と文字前処理 | `--combine --outline-text`を併用可能にし、全ページの前処理を1回だけ実施。選択順序を保持 | レイヤー付きPDFのGhostscript前処理は依然として拒否。標準の文字アウトラインはレイヤー保持 |
| 中断・制限時間 | CLIの`--timeout 秒`は別プロセスで実行し、超過時に子プロセス群を停止して一式を公開しない。Ctrl+Cでも仮保存を片付ける | 公開・復元中にタイムアウトで強制停止する設計にはしない |
| ScribusのPDF作成中 | 独立した進捗画面で中止・制限時間超過を受け付け、PDF作成終了後のAI変換へ進まない。画面終了直前の中止要求も確認 | Scribusの同期PDF作成APIそのものは即座に中断できない。UIには終了待ちになることを表示 |
| 多数ページの処理 | Scribusのページ別事前検査を、ページごとのPDF開き直しから1回の読込みへ変更。結合の色正規化済みPDFは必要な画像化が発生した時だけ1回保存して再利用 | 全ページのモデルを持つ結合方式・既存の容量上限は維持。無制限対応ではない |
| TOYOの表示と編集データ | 登録済みCMYK入力の代替値を独立したTOYO Lab値へそろえ、PDF表示と編集データを一致。正しいLab入力は元の値を保持 | 元のCMYK代替値の表示をそのまま残す方式から変更。実物の全色校正は未実施 |
| 別環境の検証 | 既存の3 OS×3 PythonのCIに結果保存を追加し、3 OSのQt連携テストと旧依存ライブラリ系列のテストを追加。PyMuPDF下限を実際に使用するモジュール名に合わせて1.24.3へ修正 | 今回のローカル環境でWindows/Linuxや別Illustrator版を実行したわけではない。CI追加と実行成功は別 |

DICとTOYOの処理・JSON・パレットは別ファイル。CMYK版パレットXMLは生成していない。ユーザーの参考用AIは変更していない。

## 検証結果

最終の自動テストは448件成功。実装前の386件から62件追加し、既存の拒否テストは対応拡張に合わせて更新した。SWIG由来の既存の非推奨警告5件は残る。

Illustrator 30.8.2で既存182例、今回の26例、実際のDIC基準例の計209例を生成・再保存・再読込した。全例でアートボード・パス・画像・文字オブジェクト数の再読込前後が一致。追加検証で修正した画像・マスクは修正後に再確認した。209例中208例はベクター変換。1例は過去の合成PDFにレイヤーの宣言がないため従来どおり画像化した。全例の画素差0を意味しない。

- `dic1_exported.ai`の表示部分を作業用PDFへ取り出して現行ツールで再生成し、Illustrator再保存後の表示を`dic1_fromai.ai`と比較。144dpi・600dpiとも画素差0。プロセスカラーの`dic1.pdf`とは別の検証。
- インライン画像2例、画像別名2例、TOYOのCMYK入力3例、注釈の外観1例、特殊な線の一部は144dpi・600dpiで画素差0。
- マスク2例の600dpi平均画素差は約0.2324と0.1992（0〜255）。差16超の画素は0%。整数倍でないマスクの追加例は600dpiのMuPDF比較で平均差約0.3869、差16超の画素約0.240%。Ghostscript比較では平均差約0.2961、差16超の画素0%。構造を保持しても描画器ごとの境界処理・丸め差は残る。丸い輪郭の線端・折返しにも既存のBezier近似差が残る。
- ページ透明グループ6例はGhostscriptによる元PDF／再保存PDFの144dpi比較で画素差0。MuPDFは元のページ直下のノックアウトを同じように表示しない例があるため、出力PDFでは同じ意味のFormグループへ移した。修正後のMuPDF比較も平均差0〜約0.4222、差16超の画素0%。[Adobeのグループ属性仕様](https://opensource.adobe.com/dc-acrobat-sdk-docs/pdfstandards/pdfreference1.6.pdf)。
- Scribus 1.6.6の独立した実機プロセスで、PDF作成の進捗処理、ページ別・結合の事前検査と公開、DIC 448 CMYK特色、裁ち落とし・トンボを確認。中止・タイムアウトは別の自動テストで確認。

詳細：`output/fidelity-check/after/medium-final/current-144dpi.json`、`medium-600dpi.json`、`medium-additional-600dpi.json`、`medium-masks-ghostscript.json`、`page-group-ghostscript.json`、`page-group-mupdf.json`、`illustrator/results-current.tsv`、`output/scribus-smoke/smoke-result.json`。初期試行の比較記録も残しているため、最新の上記ファイルを参照する。

## 大容量の計測

別プロセスで合成データを計測。元の制作ファイルを計測した数値ではない。上限を外す変更はしていない。

| 入力 | 事前検査 | 結合AI変換 | プロセス最大メモリー |
| --- | --- | --- | --- |
| 2ページ・36,000矩形パス | 約1.16秒 | 約2.17秒 | 約430MiB |
| 100ページ・計2,000パス | 約0.11秒 | 約0.16秒 | 約88MiB |

保存サイズはそれぞれ約174KB、91KB。画像・フォント・曲線の多いファイルでは別の結果になる。`tools/benchmark_conversion.py`と`output/medium-benchmark.json`に計測方法・環境・生の数値を記録した。

## 再検証

`project`から実行する。Illustratorによる保存は別途アプリ内で`tools/illustrator_fidelity_check.jsx`を実行する。作業用の検証AIだけを保存する。

```sh
.venv/bin/python -m pytest -q
.venv/bin/python tools/prepare_current_verification.py output/fidelity-check/after/medium-final --reference-ai ../dic1_exported.ai --expected-ai ../dic1_fromai.ai
# Illustratorで保存・再読込した後
.venv/bin/python tools/compare_fidelity.py output/fidelity-check/after/medium-final
.venv/bin/python tools/compare_fidelity.py output/fidelity-check/after/medium-final --renderer ghostscript
.venv/bin/python tools/benchmark_conversion.py
```

画面比較と再保存確認は、印刷の分版・OutputIntent・実物の色校正を代替しない。特異な画像マスク、ヘアライン、レイヤーを含むページ透明グループ、レイヤー付きPDFのGhostscript前処理、別アプリ版・OS・ネットワーク保存先の実機確認は残る。

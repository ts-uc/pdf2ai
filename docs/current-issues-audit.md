## 確認済みの外観差・未解決の報告

1. RGB文書内のCMYK透過画像はIllustrator再保存時の色が変動する。過去の平均画素差は0.44785と3.74107など。カラー設定・保存時の色空間との関係が未解明。
2. ユーザーのDIC 448の文字が太く見える実例は未確認。合成例では再現せず、原因と対策は未確定。
3. DIC名を同梱Labスウォッチへ対応付けるため、元PDFのCMYK代替表示とAI編集後の表示に差が出る場合がある。失われた特色名をプロセスCMYKから復元することはできない。
4. 非等方曲線・文字の線の輪郭化には近似差がある。追加23例の144dpi比較では文字の線の平均画素差0.21824〜0.23970、差が16を超える画素は最大0.572%。0.0025ptは分割基準で、最終輪郭の最大誤差保証ではない。
5. 丸い線端・結合・点、非線形グラデーション、Matte復元、16→8ビット変換にも近似・量子化差がある。

## ベクター変換の未対応・制限

| 分野 | 現在残る対象 |
| --- | --- |
| 色空間 | 一般のICC、Lab、Cal系、DeviceN／複数インク。DIC Lab等の限定対応と汎用色管理は別 |
| 特色 | 非線形の濃度関数、対応外の代替色空間・Type 4演算。単一ページ内の同名・異なる定義は拒否 |
| オーバープリント | プロセス色のモード0は未対応。印刷結果の分版検証も不足 |
| 色処理の属性 | ExtGStateのRI（レンダリング意図）とFL（平坦度）は引き継がず読み飛ばす。その他の未対応ExtGState属性は拒否 |
| 透明 | 図形のソフトマスク、分離／ノックアウトの透明グループ、Form全体への透明度・描画モード。ページ透明グループの色空間にも制限 |
| 塗りと線の合成 | 同時描画を別操作へ分割する必要があり、透明度または通常以外の描画モードがある場合は拒否。単に塗りと線を個別保持するだけでは合成を再現できない |
| 文字 | 全て輪郭化し文字として再編集できない。縦書き、Type3、Identity-H以外のCID、一部のCMap／符号化／CFF行列・字形マッピング、標準対応外の未埋め込みフォント |
| 線 | ヘアライン、グラデーションの線、非等方の180度折り返し結合、退化した線、丸以外の線端で長さ0を含む非等方破線、特異変換、分割限界を超える曲線 |
| 線の編集性 | 輪郭化した線は線幅・破線パターンとして再編集できない。極端な尖点、自己交差、接線反転の網羅的な外観検証は未完了 |
| グラデーション | メッシュ、開始半径が0でない円形、外部／境界焦点、円形の非等方・せん断変換、Extendなし、対応外の色空間／関数／Domain、不連続停止色、近似上限超過 |
| パターン | タイルパターン、追加描画状態を持つシェーディングパターン |
| 画像 | インライン画像、画像ColorSpaceのリソース別名、対応外のビット深度・色空間・フィルター／Decode。IndexedのDecode／Matte |
| 画像マスク | 異なる寸法のマスク、グレー以外のソフトマスク、入れ子のマスク、ハード・ソフトマスク併用、対応外の硬いマスク／Decode |
| ステンシル画像 | 補間指定付きは画像化。矩形パスへの展開は容量上限があり、大量の矩形になる |
| レイヤー | OCMD条件式、別レイヤー条件の入れ子、排他表示、ズーム・言語等の自動表示。元のレイヤー階層・複数表示構成の完全な再現は確認できていない |
| パス／PDF命令 | closepath後の同一サブパス継続、対応外のPDF演算子、未完了パスを跨ぐ一部操作などを拒否 |
| PDF固有情報 | 注釈付きページは画像化。リンク、フォーム入力、対話機能をAI編集データに再構築しない。PDF/Xの適合性を再認証しない |
| 入力 | 暗号化PDFは未対応。パスワードを渡す入口がない。壊れたPDF・未知の構造への回復は限定的 |

不正な数値、壊れたマスク、未定義リソース、状態の不整合等を拒否すること自体は不具合ではない。合法な未対応機能と破損入力を区別した診断は改善の余地がある。

## 画像化と出力構造に伴う損失

- 未対応を1つでも検出すると原則ページ全体をRGB画像にする。対応部分だけを残す部分画像化はない。
- 画像化したページでは文字・パスの編集、特色分版、レイヤー構造が失われる。既定300dpiは全用途の精度保証ではない。
- 元PDFを保持する表示部分と、AIの編集データは別である。元PDFの見た目が正しくても、Illustrator編集・再保存後の一致を意味しない。
- Ghostscriptの補助的な文字アウトライン前処理はPDFレイヤーと併用できない。前処理で変換結果が変わる可能性も残る。
- AI出力は実験的な形式生成であり、Illustratorの全オブジェクト機能を復元しない。Scribusの文字枠・連結・スタイルなどをそのまま保持する経路ではない。

## Scribus・画面・運用

- Scribus書き出しはPDF 1.5、文字輪郭化、ICC埋め込み無効、裁ち落とし・トンボなしに固定。これらを画面で選ぶ機能はない。
- strictと画像化解像度はScribusスクリプト内の定数設定であり、書き出し画面にはない。
- Scribus変換の子プロセスは完了待ちで、実行中のキャンセル・ページ単位の詳細進捗・処理タイムアウトは未実装。
- ページ別出力では一部だけ成功する場合がある。一式を全成功時だけ公開する方式ではない。
- 通常CLI／Tk GUIは対象1ページの変換であり、Scribusと同じ全ページ／範囲選択・結合の入口がない。内部の複数アートボードAPIとは別。
- Tk GUIには画像化dpi・JSON出力・上書き確認・処理中キャンセルの設定がない。同名の入力は同じ出力名になるため衝突する。
- CLIのJSONレポートは直接書き込みで、Scribus側のレポートのような原子的公開ではない。出力先競合の検査は変換処理後、書き込み失敗の扱いにも改善余地がある。
- レポートの画像化理由は最初に遭遇した拒否条件であり、そのページの全未対応機能を事前列挙する機能ではない。
- レポートで輪郭化を記録できるが、全近似処理の誤差見積もりや印刷適合性の総合判定はない。

## 容量・性能

- 結合は最大1000アートボード、14400pt四方への配置が必要。同名特色の定義がページ間で違うと結合できない。
- 単ページでも座標／UserUnitに上限があり、大型キャンバスへの対応は限定的。
- 画像と画像化は4000万画素まで。高dpi・大判では画像化も失敗する。
- サブパスは8191コマンド、曲線分割深さ22、破線展開・輪郭・ステンシルにも上限がある。Formの再帰／深い入れ子は拒否。
- 曲線・破線・文字の輪郭化でオブジェクト数とAI容量が増える。大規模実データの速度・メモリ・長時間処理の評価が不足。

## 未検証・検証方法の課題

- 実機はIllustrator 30.8.2、Scribus 1.6.6が中心。CC2020を含む他版、Windows／Linuxの実機、Python／依存ライブラリの組合せの確認が不足。
- 215自動テスト、14ページ統合サンプル、累計147件の実機ケースは有限の例である。147件全てを最終修正後に一括再実行した結果ではない。
- 144dpi・RGB画素比較は画面の外観評価。高解像度の細部、分版、オーバープリント、印刷のカラー設定、OutputIntent、実入稿工程の保証ではない。
- 合成ケース中心で、実制作PDF・SLA、和文フォント、複雑な透明・レイヤーの組合せ、多数ページへの試験が不足。
- 画像ColorSpace別名の実験は描画器間の解釈差が大きく採用を撤回した。仕様・参照スコープ・描画器の挙動の切り分けが残る。
- 古い検証記録には当時の未対応一覧が残る。最新の対応は現行ソースと最新追記を優先する必要があり、技術文書の「線は等方変換のみ」等も現状に追随していない。

## 優先順位

1. 外観・入稿に直結するCMYK画像の色差、DIC 448実例の切り分け、分版・オーバープリント・ICCの検証。
2. ページ全体画像化を減らす透明グループ／図形ソフトマスク、画像の対応拡張。
3. 実データでの一括回帰検証、曲線近似の誤差・性能評価、未対応機能の事前検査。
4. 文字の編集可能性、汎用色管理など設計変更を伴う機能。
5. 裁ち落とし設定、GUI／CLIのページ出力統一、キャンセル、レポートと文書の整備。

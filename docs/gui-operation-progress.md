# GUIの進捗・エラー表示の改善

後続の再点検による入力・終了処理の修正と最新の検証件数は[再点検の対応記録](automatic-review-fixes.md)を参照。

2026-10-11。「取り組みやすいもの」の依頼で、通常のTk GUIの操作と通知を改善した。

## 変更

- 処理開始時に入力ファイルと対象ページを表示。ページ別出力・結合の両方で進捗バーを更新する。
- 結合時の進捗は「解析済み・AIは未保存」と明示。保存成功後だけ保存済みページ数を増やす。
- 終了時に保存・失敗・未処理ページ数と経過秒数を表示。レポートだけ保存できなかった場合もエラーありとして表示する。
- エラーにファイル名・対象ページを付ける。解像度の入力エラーは許容範囲を示す。暗号化PDFは計画段階で日本語の未対応メッセージを返す。
- 処理中は入力と設定の変更を無効にする。キャンセル後は停止待ちの表示を維持する。
- 実行中にウィンドウを閉じようとした場合、終了せずキャンセルを要求する。停止後にもう一度閉じる。内部の長時間処理を即時終了する機能ではない。
- GUIのページ番号付き出力名をCLIと揃える。ページ指定が空欄の単ページは従来の`name.ai`、`1`や`all`を指定した場合は`name_001.ai`になる。
- キャンセル時のJSONには、保存済み・失敗・未処理の件数を持つ`cancelled: true`の記録を追加する。AIの保存結果とは別の終了状態の記録。

変換処理と画面通知を`src/pdf2ai/gui_jobs.py`へ分離した。UIの更新は引き続きTkのメインスレッドだけで行い、変換スレッドはイベントをキューへ送る。

## 検証と制限

- 全自動テスト277件、統合サンプル14ページ成功。
- GUI処理の追加テスト8件。実際のPDF変換を使い、途中のページ失敗後の継続、結合解析中のキャンセルと既存AI保護、レポート保存失敗時のAI保持と終了通知を確認。
- 出力名、計画段階の競合、入力ファイル名付き診断、暗号化PDFを確認。
- `gui.py`と`gui_jobs.py`の構文チェック成功。

現行の`.venv`はPython 3.14で、`_tkinter`がない。Tk GUIの起動・目視・クリック操作は確認できていない。これらのテストは実際の変換処理と通知イベントを検証するもので、画面配置やGUI操作の実機検証ではない。実制作PDFやDIC 448の報告実例、他OSでの確認も今回追加した検証には含めない。

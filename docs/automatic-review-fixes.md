# 再点検で見つかった不具合の修正

単独のデスクトップGUIは後続作業で削除した。以下のTk GUI関連の記述は履歴で、現行機能・残課題ではない。[削除の記録](desktop-gui-removal.md)。

2026-10-11。「自動で直すところをもう一度調べて」の依頼に対する追加点検。CLI・単ページAPI・結合・GUIの計画と終了通知・Scribusの出力先検査を確認した。全入力・全機能に不具合がないという監査ではない。

## 修正した不具合

1. CLIでパスワード付きPDFを開く際、PasswordErrorはPdfErrorの派生型ではないため、既存の例外処理を通らなかった。単ページ・ページ別・結合・事前検査で診断を返し、終了コード1にする。パスワード入力や暗号化PDFの変換を追加したわけではない。
2. 0ページPDFの`--pages all`が空の処理計画になり、AIを作らず成功扱いだった。ページ選択段階で拒否する。単ページAPIも0ページを明示診断する。
3. `--pages ''`等の明示的な空指定が、未指定として扱われる経路があった。空指定を拒否し、`--page`との同時指定も区別する。`all`の前後の空白は取り除く。
4. `--pages`では出力ベース名の拡張子が書き換わり、`-o out.pdf`でも`out_001.ai`が作られた。ベース名が`.ai`かを展開前に検証する。
5. 単ページAPIのページ番号0やTrueが1ページ目として扱われることがあった。正の整数だけを受け入れ、浮動小数点・文字列等も拒否する。無効な指定では既存AIを保持する。
6. 出力AIやレポートと同名のフォルダーがある場合、変換後の保存で初めて失敗する経路があった。CLI・GUI計画・単ページ／結合API・Scribusの各入口で事前に拒否する。Scribusは一部のページだけ保存される前に全出力先を検査する。
7. GUIワーカーの予期しない中断が、終了イベントでは成功に見える場合があった。worker_errorを記録し、未処理ページも成功扱いにしない。
8. GUIの処理スレッド開始に失敗した場合、操作部が無効のままになる経路があった。失敗通知と終了通知をキューへ送り、操作部を復帰させる。

CLIの画像化dpiも変換前に検査する。画像表現や色管理の未対応範囲を広げる変更ではない。

## 検証

- 自動テスト302件成功。今回の再現テストは25件（再点検22件、Scribusのフォルダー衝突3件）。
- 統合サンプル14ページ成功。通常のベクター変換と未対応ページの画像化を確認。
- GUI・CLI・Scribusスクリプトの構文チェック成功。
- 出力を作らず診断すること、無効なページ番号や出力先で既存データを保持すること、GUIワーカーの致命的エラーでも終了イベントを送ることを確認。

Tkがないため、GUI画面の起動・目視・クリック確認、およびスレッド開始失敗からの画面復帰の実機確認はできていない。今回はIllustratorでの追加保存検証をしていない。今回の主な変更は描画データの生成ではなく、入力検査と終了処理である。実制作PDF、DIC 448、分版・実印刷、特殊な描画の未対応は引き続き残る。

残る互換性は[compatibility-gaps.md](compatibility-gaps.md)、後続のGUI削除は[削除の記録](desktop-gui-removal.md)を参照。

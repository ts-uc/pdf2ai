# 追加の画像・運用改善

2026-10-11。「難しそうなもの以外」の依頼で、既存の画像読み取りと運用機能を拡張した。全互換性の完了報告ではない。

## 後続の小規模修正

「小さい修正で解決できるもの」の追加依頼で、以下を修正した。

- 16ビット画像と16ビットソフトマスクのDecodeを、8ビットへ丸める前の元サンプルへ適用。先に丸めた値にDecodeを適用する二重丸めを避ける。AIに格納する最終値は引き続き8ビット。
- 壊れたIndexedパレットや不完全な画像ColorSpace配列をConversionErrorとして診断。事前検査で理由を返し、strict変換では既存AIを保持する。
- 事前検査のdpiとページ重複を検証。変換で拒否される設定を事前検査だけが受け入れないようにし、対応ページのplanned_modeも明示する。

全自動テスト269件、統合14ページ成功。16ビットDecodeの1例はIllustrator 30.8.2で保存・再オープンし、パス1・画像1を保持。144dpiの平均画素差は0.19107（RGB 0〜255）、差16超の画素0%。PDF描画器との丸め順序の差を含み、外観の完全一致や平均画素差の改善を示した検証ではない。

生成ツールは`tools/make_16bit_image_cases.py`。検証記録は`output/fidelity-check/after/image16-conversion.json`、`image16-visual.json`、`illustrator/results-image16.tsv`。

16ビット画像の色キーマスクも試作したが、隣接する1000／1001のサンプルを、元PDFの描画器が同じ透明色として扱う例があった。元サンプルを厳密比較した試作の再保存PDFではこの2値を区別し、平均画素差18.725〜29.23393が出た。試作を採用せず、16ビット色キーマスクはstrict拒否／ページ画像化を維持する。試作と比較結果は`output/fidelity-check/after/image16-mask-experiment/`へ隔離した。

## 今回対応した項目

- RGB／CMYK／グレー画像の1／2／4ビットサンプル。行末パディング、Decode、元サンプルによる色キーマスク判定に対応。
- Indexed画像のDecode。反転や範囲指定、丸め・パレット範囲への制限を適用。透明色の判定にはDecode前の番号を使う。大きな画像の展開で画素ごとの中間リストを作らない。
- RGB／CMYKページの結合。結合後の文書がRGBならCMYK画像を明示変換し、ページ別レポートに変換内容とcombined_color_modelを記録。透明グループの色空間が結合文書と異なる場合は、外観を変えて出力せずページ別出力を案内する。
- Tk GUIのキャンセル。単ページ処理は保存前、結合はページ間・結合処理前・保存前で確認する。キャンセルを画像化理由として扱わず、未保存AIは公開しない。結合中は処理済みページ数も表示する。
- Scribusの変換制限時間。設定画面で0〜1440分を選択。初期値0は制限なし。タイムアウトで子プロセスを終了し、ページ別出力の完了分が残る可能性を明示する。PDF書き出しや設定ダイアログの制限時間ではない。
- 外観比較ツールにケース選択と別名レポートを追加。今回の比較結果を過去の結果と分けて保存できる。
- 最新の未対応一覧を更新。過去の監査や途中経過は履歴として保持する。

## 検証

全自動テスト254件、統合サンプル14ページが成功。追加の自動テストはサンプル・パディング・Decode・色キーマスク、入力属性の復元、キャンセル時の既存AI保護、結合の色変換と色空間不整合の拒否、Qt設定画面、子プロセスのタイムアウトを確認する。

画像5例をIllustrator 30.8.2で保存・再オープンし、パス1・画像1を保持。元PDFと再保存PDFの144dpi比較は5例とも平均画素差0、差16超の画素0%。この有限の比較は他の入力や印刷結果の保証ではない。

- 生成ツール：`tools/make_packed_image_cases.py`
- 変換レポート：`output/fidelity-check/after/packed-image-conversion.json`
- 実機の構造確認：`output/fidelity-check/after/illustrator/results-packed-images.tsv`
- 外観比較：`output/fidelity-check/after/packed-image-visual.json`

Tkの手動操作、Scribus実機でのタイムアウト操作、混合色空間の結合AI再保存は今回未検証。自動テストと画像5例の実機確認とは区別する。

## 残した項目と理由

| 残る対象 | 今回の小規模拡張に含めない理由 |
| --- | --- |
| 文字の再編集、和文・縦書き・特殊フォント | Illustrator文字エンジンの字形・配置キャッシュ、フォント対応の再設計が必要 |
| ICCグラデーション、Lab／Cal系／DeviceN、元ICC・CMYK成分の編集保持、OutputIntent | 非線形の色変換・補間・文書の色管理を一緒に検証する必要がある |
| 図形ソフトマスク、ページの分離／ノックアウト、異なる色空間の透明グループ | 合成順序・色空間・クリッピングを変更するため、保存成功だけでは判断できない |
| 寸法が異なるマスク、Indexed Matte、特殊フィルター、ColorSpace別名、インライン画像 | サンプル位置・補間、元色の復元、リソース参照やデコーダー差の外観検証が必要。別名の過去試作では大きな差が出た |
| メッシュ、タイルパターン、特殊な線・グラデーション、部分画像化 | 新しいオブジェクト表現または描画構造の組み替えが必要 |
| 条件付きレイヤー、全未対応理由の網羅的な事前列挙 | 条件評価と、エラー後も安全に状態を継続できる検査器が必要 |
| 単ページ内部の即時キャンセル、Scribus進捗・手動キャンセル、一括出力の全成功時公開 | 長い描画処理の中断、別プロセスとの通信、複数ファイルの公開・復元方式が必要。現在は安全な境界での停止と任意のタイムアウト |
| 暗号化PDF、注釈・入力フォームの編集再現、容量上限の撤廃 | パスワードの受け渡し・表示情報との整合性、AIにないPDF機能の扱い、メモリ・座標の制約を含む設計が必要 |
| DIC 448実例、分版・実印刷、他OS／他版、大規模実データ | 実例・対象環境・印刷工程を使った検証が必要。合成例のテストだけで解決としない |

現行の互換性一覧は[compatibility-gaps.md](compatibility-gaps.md)、直前の色管理と透明グループの成果は[color-transparency-text-progress.md](color-transparency-text-progress.md)を参照。

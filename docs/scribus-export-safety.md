# Scribusの事前検査・一括公開・進捗とキャンセル

2026-10-11。Scribus書き出しの運用改善3項目への対応。画像・文字等の描画互換性の拡張とは別である。

## 書き出し前チェック

Scribusが一時PDFを作成した後、各ページを既存のパーサーとAI書き込み検証へ渡す。元の文書ページ番号を保持し、ベクター対応可否と最初の拒否理由、警告を確認画面に表示する。画像化禁止なら未対応ページがあると書き出せない。許可する場合は編集性の損失を確認して続行できる。

このチェックは全拒否理由の列挙、印刷品質の保証ではない。結合のキャンバス配置、同名特色の不整合、文書とグループの色空間の不整合などは変換時にも検査し、失敗すればAIを公開しない。

## 一括公開と復元

各AIは一時フォルダーへ生成する。すべての変換が成功した場合だけ最終保存先へ公開する。成功時のJSONレポートも同じ公開処理へ含め、レポート保存失敗時にもAIを戻す。上書き前に既存ファイルのバックアップを作り、公開途中の通常の失敗・KeyboardInterruptでは、変更済みファイルを元に戻し、新規公開分を取り除く。

変換に失敗した場合、正常に変換できたページも`published: false`として公開しない。JSONログを有効にしていれば、`committed: false`の診断レポートだけを保存する。ログを無効にした場合は既存ログを変更しない。

復元そのものが失敗した場合は、`.pdf2ai-recovery-…`にバックアップと保存先一覧を保持し、エラーで場所を通知する。複数ファイルの公開は順次実行され、外部から見た同時切替は保証しない。電源断・OS強制終了・別プロセスによる並行書き換えからの完全な復元も保証しない。

## 進捗とキャンセル

Scribus専用の外部Qt進捗画面がQProcessで検査・変換の子プロセスを管理する。画面は応答し、検査・変換ページ数を表示する。検査中・変換中・公開待ちのキャンセルは子プロセスを停止し、AIを公開しない。一時出力はScribus側の作業フォルダーとともに破棄する。

公開開始には進捗画面からの許可ファイルを必要とする。先にキャンセル・タイマーを無効化してから許可を渡し、変換終了通知とキャンセルが近接しても、公開中に子プロセスを終了しない。

制限時間は検査・変換それぞれに適用し、0は制限なし。PDF作成、確認操作の待ち時間、保存・復元中には適用しない。Scribus自身のPDF書き出し中をキャンセルする機能ではない。Scribus本体の既存進捗バーは段階表示で、ページ詳細とキャンセルは連携用のQt画面で扱う。削除した単独Tk GUIは復活させていない。

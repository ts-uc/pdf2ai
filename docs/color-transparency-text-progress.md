# 色管理・透明処理・文字の再編集の対応状況

2026-10-11。4項目の解決依頼への実装・実機検証。文字の再編集を含む全項目の完了報告ではない。

## 実装した変更

### RGB文書内のCMYK画像

Illustratorの読み込み・保存時の自動変換へ委ねず、PDF検証に使うMuPDFのDeviceCMYK→RGB変換を先に適用する。透過マスクと配置は保持し、画像以外はベクターのまま残す。CMYK文書の画像は従来どおりCMYKを保持する。

検証例の平均画素差は0.09144（RGB 0〜255、144dpi）。以前の同種ケースは3.74107等へ変動していた。今回の実機検証で大幅に差を減らしたが、全ファイル・他の作業用プロファイル・OutputIntent・印刷設定までの一致を保証しない。RGBへの変換後は元のCMYK4成分として画像を編集できない。変換内容はレポートの`color_conversions`へ記録する。

### ICC

RGB／CMYK／グレーのICCBased画像とベクターの塗り・線をLittleCMSでsRGBへ変換する。非線形のプロファイルの変換はLittleCMSへ委ねる。黒点補正を有効にし、PDFのレンダリング意図を適用する。`ri`またはExtGStateのRIが色指定後に変更された場合も再評価する。DefaultRGB／DefaultCMYK／DefaultGrayに設定されたICCを、直接の色命令と画像で参照する。

画像はDecode・マスク・Matte処理後に変換し、元PDFの画像ColorSpace等の属性は戻す。変換先は8ビットsRGBで、元ICCとその成分値をAI編集データの色プロファイルとして保持する実装ではない。元PDF表示部分のリソースは保持する。ICC付きグラデーション、Lab等のモデル、非標準Range、汎用ICCの全機能は未対応。

実機はAdobe RGB (1998)のRGB画像・塗りと、ISO Coated v2のCMYK画像・塗りで比較。平均画素差0.04324〜0.27083。ICCプロファイル自体は外部アプリのローカルファイルからテスト入力として取得し、プロジェクトの実行時依存として要求しない。入力PDFに埋め込まれたプロファイルを利用する。

### 透明グループ

Form透明グループの分離、ノックアウト、不透明度、描画モード、入れ子をAIのグループへ出力する。親グループの透明度を子へ重複適用しない。グループの塗り不透明度をグループ描画に適用し、内部の描画状態は透明度1・Normalから開始する。

半透明の塗りと線を分割する場合は、暗黙のノックアウトを明示的なグループで保持する。輪郭化した非等方線、文字の輪郭にも適用する。過去の回帰例で平均画素差1.61463→0.10453。追加8例の平均は0.03022〜0.31258。文字は輪郭であり、ここで文字編集が可能になったわけではない。

文書と異なるグループ色空間、グループ内のレイヤー切替、図形のソフトマスク、ページ全体の分離／ノックアウトは引き続き拒否または画像化する。特色分版・オーバープリントとの複合条件の印刷検証も残る。

## 文字の再編集：未完了

旧AIのTo／Tx命令を現行AIへ追加する方法は、Illustratorが文字オブジェクトとして保持しなかった。AI24の文字エンジン用データを含める試作では、文字オブジェクト1つの保存・再オープンに成功した。

しかし、文字列だけを変更するとキャッシュされた字形・配置と不整合が起きる。改行形式が不正な試作では読み込みエラーになり、形式を直した試作でも文字列と再保存PDFの表示が一致しない例がある。任意の文字、フォント、行列、文字間隔、クリッピングへ一般化できていない。試作は通常変換に組み込まず、`output/fidelity-check/after/text-experiment/`へ隔離した。AIの名前を付けたPDFを、ネイティブ文字対応として採用することもしていない。

元の文字意味がPDFに記録されていないフォント、欠落したUnicode対応、縦書き・複雑な字形なども検討が必要。現状の標準変換では文字は輪郭化され、文字としての再編集はまだできない。
